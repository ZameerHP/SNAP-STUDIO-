SUPER SNAP STUDIO — CONNECTION GUIDE

Implemented: React/TypeScript public website, GSAP/Lenis scroll scenes, persistent enquiries, owner/client authorization, client assignments, private media uploads, image/video galleries, favorites/selections, download permissions, explicit public publishing, project messages, invoices and PDF download, configurable content.

Sign-in: This version uses ChatGPT sign-in. Clients must use the exact email that the owner assigned to their client record. User IDs are linked on first verified sign-in. There is no shared administrator password. The owner is selected by the server-only OWNER_EMAIL environment variable. The initial owner is the site creator. Set OWNER_EMAIL to the studio owner before handover.

This Site is initially private to its creator. Before inviting clients, explicitly set its audience using Sites sharing settings. Client roles still require an assignment by the studio. The private audience also prevents external providers from reaching webhooks; public access must be deliberately enabled before those integrations can go live.

STORAGE
D1 DB owns records. R2 BUCKET owns original image and video bytes. Migrations are in drizzle/. No client media is public until its project is explicitly published. Every private media request is authorized on the server. Downloads cannot prevent screenshots. Uploads accept JPEG, PNG, WebP, MP4, WebM, at most 25 MB per file.

PAYMENTS — SQUARE (credentials not connected)
Stripe checkout has been removed. Payments use a Square-hosted checkout page and settle to the studio seller account connected by its Square access token and location.

Set the following in Sites production runtime environment variables (server-only):
SQUARE_ENVIRONMENT=sandbox or production
SQUARE_ACCESS_TOKEN=the matching Square application access token (secret)
SQUARE_LOCATION_ID=the studio's active, card-processing-enabled Square location
SQUARE_WEBHOOK_SIGNATURE_KEY=the webhook subscription Signature Key (secret)
SQUARE_WEBHOOK_URL=https://YOUR-SITE/api/webhooks/square
SITE_URL=https://YOUR-SITE

Create the application in the studio owner's Square Developer Console, not an unrelated seller account. Credentials and Locations sections provide the token and location ID. Under Webhooks, create a subscription for the exact SQUARE_WEBHOOK_URL and copy its Signature Key. Subscribe to payment.created, payment.updated, refund.created, refund.updated. All credentials and the subscription must use the same sandbox/production environment. The API version used by this build is 2026-09-16.

The current hosted redirect checkout does not need a browser Application ID, application secret, Web Payments SDK, or Stripe key. A future embedded card form or multi-seller OAuth connection would have different requirements.

The website uses Checkout API, Payments API, Orders API, and Locations API. For a scoped OAuth implementation the relevant permissions are ORDERS_READ, ORDERS_WRITE, PAYMENTS_READ, PAYMENTS_WRITE, and MERCHANT_PROFILE_READ. This one-studio build uses the seller's own application token and does not implement an OAuth connection flow.

Invoice currency must match the Square location currency. For a Canadian studio location this is normally CAD; confirm in Square. The server calculates the deposit/balance, persists checkout attempts and idempotency keys, serializes concurrent requests, verifies HMAC callbacks, re-fetches payments/orders, and records each payment once. It checks order, amount, location, and currency. A browser redirect cannot mark an invoice paid. Refunds are initiated in Square, then reconciled into the website. Unrelated in-person Square payments do not automatically attach to website invoices. Website PDF invoices remain in this website; this integration does not create Square Invoices API objects.

Test in Square Sandbox: deposit, remaining balance, full payment, failed/cancelled checkout, simultaneous pay clicks, switching deposit/full payment, provider timeout/retry, duplicate callbacks, wrong signatures, partial/full refunds, and a mismatched currency. Then configure production credentials for the same studio account. No live payment has been tested or collected in this build. Square processing fees and payout rules apply.

EMAIL (not connected)
Set RESEND_API_KEY and EMAIL_FROM to a verified sender. The supplied Gmail address is Reply-To, not an assumed verified sending domain.
Outgoing emails are sent only by an explicit owner action. Enquiry submission saves the request, but does not automatically email anybody.
For incoming mail, configure a receiving domain in Resend and RESEND_WEBHOOK_SECRET.
Resend webhook: /api/webhooks/resend
Events: email.received and relevant delivery/bounce events. Inbound mail is not an authenticated Gmail connection. Messages without a matched client remain owner-only. Webhook signatures are verified against the raw body.

SIGNATURES (not connected)
Set DOCUSEAL_API_KEY and DOCUSEAL_WEBHOOK_SECRET (HMAC signing secret).
DocuSeal webhook: /api/webhooks/docuseal
Create a prepared one-signer template in DocuSeal. Use its template ID in the owner dashboard. Completion is re-fetched from the provider after a verified callback. Signed document and audit links appear only once confirmed.

CONTENT
Replace demonstration images with licensed studio portfolio media. Credits are at /image-credits.txt. Set a real video URL in Settings to enable the film player. No studio showreel, awards, prices, or testimonials are invented.
